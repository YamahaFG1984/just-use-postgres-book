基础

实例 / 数据库集簇 instance / database cluster
一个运行中的 Postgres 服务器，里面可以有多个数据库。角色属于整个实例。第 2 章
数据库 database
实例里相互隔离的一组对象。一个连接只能连一个库，跨库查询需要扩展（如 postgres_fdw）。第 2 章
模式 schema
数据库里的“命名空间”，用来给表分组，如 sales.orders。默认是 public。第 2 章
行 / 元组 row / tuple
表里的一条记录。Postgres 内部文档常称 tuple，一行可以有多个版本（见 MVCC）。专题 4
主键 / 外键 primary key / foreign key
主键唯一标识一行；外键要求列值必须在另一张表的主键（或唯一键）里存在。第 2 章
约束 constraint
数据库强制的规则：NOT NULL、UNIQUE、CHECK、主键、外键、排他约束 EXCLUDE。第 2 章
角色 / 权限 role / privilege
Postgres 里用户和用户组都是角色；用 GRANT / REVOKE 授予或收回对库、模式、表的权限。第 2 章
视图 / 物化视图 view / materialized view
视图是存起来的查询，每次访问时执行；物化视图把结果存成表，需要 REFRESH 更新。第 2 章
函数 / 存储过程 / 触发器 function / procedure / trigger
在数据库里运行的代码（常用 PL/pgSQL）；触发器在 INSERT/UPDATE/DELETE 时自动调用函数。第 2 章
扩展 extension
给 Postgres 增加类型、函数、索引方法的插件，用 CREATE EXTENSION 安装到某个库。第 7 章
psql
Postgres 自带的命令行客户端，\ 开头的是它自己的命令，不是 SQL。第 1 章、速查表
SQLSTATE
每个错误附带的 5 位代码，如 23505 唯一冲突、40001 串行化失败。应用应按它而不是错误文字处理错误。专题 5

查询

连接 JOIN
按条件把多张表的行拼起来：INNER（两边都匹配）、LEFT（左表全保留）、FULL、CROSS 等。第 2 章
公用表表达式 CTE, WITH 子句
用 WITH 给子查询起名字，让复杂查询分步书写。第 3 章
递归查询 recursive CTE
WITH RECURSIVE：结果不断引用自己，直到不再产生新行。用于树、层级、图。第 3 章
窗口函数 window function
带 OVER (…) 的函数，在一组相关行上计算（排名、累计、前后行），但不把行合并。第 3 章
UPSERT INSERT … ON CONFLICT
“存在就更新、不存在就插入”，借助唯一索引在并发下也是原子的。专题 2
规划器 / 执行计划 planner / query plan
规划器根据统计信息估算成本，为每条查询挑一个执行计划；EXPLAIN 显示它。第 4 章
EXPLAIN / EXPLAIN ANALYZE
前者只显示计划和估算；加 ANALYZE 会真的执行，显示实际行数和耗时。附录 A.1
统计信息 statistics, ANALYZE
每列的值分布摘要，规划器靠它估算行数。ANALYZE（autovacuum 也会自动做）负责更新。第 4 章
顺序扫描 / 索引扫描 / 位图扫描 Seq Scan / Index Scan / Bitmap Heap Scan
读整张表；按索引逐行回表；先用索引收集所有位置再按物理顺序读表。第 4 章

索引

B-tree
默认的索引类型，支持等值、范围、排序、前缀 LIKE。第 4 章
GIN Generalized Inverted Index
倒排索引：一个值（键、元素、词素）对应包含它的所有行。用于 JSONB、数组、全文搜索、pg_trgm。第 5 章
GiST Generalized Search Tree
通用的平衡树框架，用于几何（PostGIS）、范围类型、排他约束、最近邻。第 10 章
BRIN Block Range Index
只记录每段数据块的最小 / 最大值，极小。适合按时间顺序写入的超大表。第 9 章
HNSW / IVFFlat
pgvector 的两种近似最近邻索引：HNSW 是多层图，召回好、建得慢；IVFFlat 先聚类再搜索，建得快。第 8 章
复合索引 / 最左前缀 composite index / leftmost prefix
多列索引 (a, b) 能用于只按 a、或按 a 和 b 过滤的查询，单独按 b 一般用不上。第 4 章
覆盖索引 / 仅索引扫描 covering index / Index Only Scan
查询要的列都在索引里（可用 INCLUDE 补充），无需回表读数据。第 4 章
部分索引 partial index
带 WHERE 的索引，只收录满足条件的行，更小更快。第 4 章
表达式索引 expression index
对表达式（如 lower(email)）建索引，查询里要写同样的表达式才能用上。第 4 章

事务与并发

事务 / ACID transaction
一组要么全部成功、要么全部撤销的操作。ACID 指原子性、一致性、隔离性、持久性。第 2 章
多版本并发控制 MVCC
更新时写入新版本而不是覆盖，读写互不阻塞；每个事务按自己的快照看数据。第 2 章、专题 4
快照 snapshot
某一时刻“哪些事务已提交”的视图，决定一个语句或事务能看到哪些行版本。专题 2
隔离级别 isolation level
READ COMMITTED（默认）、REPEATABLE READ、SERIALIZABLE，级别越高防住的并发现象越多。专题 2
不可重复读 / 幻读 / 写偏斜 non-repeatable read / phantom / write skew
同一行读两次不同 / 同样条件查出新行 / 两个事务各改不同行、合起来违反规则。专题 2
丢失更新 lost update
两个事务都基于旧值计算并写回，先写的结果被覆盖。用原子 UPDATE 或 FOR UPDATE 避免。专题 2
行锁 row lock, FOR UPDATE
UPDATE/DELETE 或 SELECT … FOR UPDATE 会锁住行，其他想修改它的事务要等待。专题 2
SKIP LOCKED / NOWAIT
遇到被锁的行：跳过它 / 立刻报错，而不是等待。SKIP LOCKED 是用 Postgres 做队列的关键。第 11 章
死锁 deadlock
事务互相等待对方持有的锁。Postgres 自动检测并取消其中一个（40P01）。专题 2
咨询锁 advisory lock
以数字命名、含义由应用约定的锁，用来锁“一件事”而不是某一行。专题 2
LISTEN / NOTIFY
Postgres 内置的轻量发布 / 订阅：一个会话 NOTIFY，监听该频道的会话收到通知。第 11 章

存储与运维

页 / 堆表 page / heap
数据文件按 8 KB 的页组织；表本身叫堆表（行无固定顺序），索引是独立的文件。专题 4
TOAST
一行里的大字段（长文本、大 JSON，超过约 2 KB）会被压缩或移到单独的 TOAST 表里存放。本教程未展开，见官方文档
预写日志 WAL, Write-Ahead Log
所有修改先写进 WAL 再改数据文件；用于崩溃恢复、复制和时间点恢复。专题 6
检查点 checkpoint
把内存里修改过的页写回数据文件的时刻，之前的 WAL 不再是崩溃恢复所必需。专题 6
死元组 / 表膨胀 dead tuple / bloat
已经没有事务需要的旧行版本；积累多了表和索引会变大变慢。专题 4
VACUUM / autovacuum
回收死元组空间、更新可见性映射、冻结旧行；autovacuum 是在后台自动做这件事的进程。专题 4
HOT 更新 / fillfactor heap-only tuple
被改的列没有索引、页内又有空位时，新版本放在同一页且不改索引；fillfactor 预留这个空位。专题 4
事务 ID 回卷 / 冻结 XID wraparound / freeze
32 位事务 ID 会绕圈；VACUUM 把足够老的行“冻结”以防误判。不处理会导致数据库拒绝写入。专题 4
连接池 / PgBouncer connection pool
复用数据库连接（每个连接是一个进程）；PgBouncer 是常用的服务端连接池。附录 A.3、专题 5
分区 partitioning
把一张大表按范围、列表或哈希拆成多张子表，查询和清理旧数据都更快。第 11 章
复制 / 逻辑复制 replication
物理复制传 WAL，得到一模一样的副本；逻辑复制按表传数据变更，可跨大版本。专题 6
pg_dump / pg_restore
逻辑备份与恢复工具；角色要用 pg_dumpall --globals-only 另外备份。专题 6
时间点恢复 PITR
基础备份 + 持续归档的 WAL，可以恢复到任意时刻。专题 6
行级安全 RLS, row-level security
用策略控制每个角色能看到、修改表里的哪些行，常用于多租户。专题 3

JSON、搜索、AI、时序、地理

JSON / JSONB
json 原样存文本；jsonb 解析成二进制，去掉重复键，可以建索引，绝大多数情况选 jsonb。第 5 章
JSONPath
在 JSON 里按路径和条件取值的查询语言，如 $.items[*] ? (@.price > 10)。第 5 章
tsvector / tsquery / 词素 lexeme
文档被处理成词素（归一化后的词）及位置的列表；查询也转成词素表达式，用 @@ 匹配。第 6 章
文本搜索配置 / 词典 / 分词 text search configuration / dictionary / parser
分词器把文本切成词，词典把词归一化、去掉停用词；配置把两者组合起来，如 'english'。第 6 章、专题 1
三元组 trigram, pg_trgm
把字符串切成连续 3 个字符的片段，用来算相似度、加速 LIKE '%x%'。专题 1
向量嵌入 embedding
模型把文本、图片转成的一串数字，语义相近的内容向量距离也近。第 8 章
余弦距离 / 欧氏距离 / 内积 cosine / L2 / inner product
衡量向量相似度的三种方式，pgvector 运算符分别是 <=>、<->、<#>（负内积）。第 8 章
检索增强生成 RAG
先用向量搜索找出相关资料，再把它们和问题一起交给大模型生成回答。第 8 章
超表 / 数据块 hypertable / chunk
TimescaleDB 的表，按时间自动切成许多 chunk，写入和按时间删除都更高效。第 9 章
连续聚合 continuous aggregate
TimescaleDB 的“自动增量刷新的物化视图”，常用于按小时 / 天的汇总。第 9 章
坐标参考系 / SRID spatial reference ID
说明坐标的含义，如 4326 是经纬度（WGS 84）。算距离、面积前常要 ST_Transform 到合适的投影。第 10 章
geometry / geography
PostGIS 的两种类型：geometry 在平面上计算；geography 在球面上计算，结果以米为单位。第 10 章
PGlite
编译成 WebAssembly 的 Postgres，可以在浏览器里运行，本站的练习场就是用它做的。SQL 练习场
