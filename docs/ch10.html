第 10 章

地理空间数据

空间数据描述物体在几何空间中的位置和形状，比如二维或三维欧氏空间里的点、线、多边形。 地理空间数据是其中的一个子集，专指和地球表面位置相关的地理信息（geodata）：一辆车的实际位置、一场雷暴的范围，都用经纬度坐标表示。 这一章我们用美国“阳光之州”佛罗里达的 OpenStreetMap 数据，一边规划一场从坦帕到迪士尼再到迈阿密的家庭旅行，一边学习在 Postgres 里存储、查询和处理地理数据。

本章目标

  • 理解地理数据的三种基本形状（点、线、面）和“图层”的概念
  • 了解 Postgres 内置的几何类型，以及为什么还需要 PostGIS
  • 分清 geometry 与 geography、SRID 3857 与 4326、WKT 与 WKB
  • 导入 OSM 数据，用 QGIS 可视化
  • 熟练使用 ST_Transform、ST_DWithin、ST_Distance、ST_Within、ST_Intersects 等函数
  • 理解 GiST（R-tree）空间索引，知道哪些函数能用上索引

Postgres 如何处理地理数据

地理空间数据存储的是物体在地球表面的位置和附加信息。根据位置或属性是否变化，它可以是静态的、动态的，甚至是有时间性的。 想象你周日早上在迈阿密的酒店醒来，打开 Google 地图规划一天的行程 —— 你看到的地图其实是好几层地理数据叠在一起：

  • 面：区域、建筑、公园等的位置和形状用闭合多边形表示。多边形是由直线首尾相连围成的二维图形 —— 附近的楼可能是矩形，公园和湖泊则由很多长短方向各异的线段围成。缩小地图，还能看到迈阿密的城市边界、佛罗里达的州界，以及和它相邻的墨西哥湾、大西洋。它们基本不变（建筑边界）或很少变化（街区边界），是静态地理数据。
  • 点：兴趣点、设施、地标是另一层，通常用带两个坐标的点表示，附带名称、地址、评论、评分等信息。这些点往往位于建筑（多边形）之内，一栋楼里可能有好几家店。这类数据可以算静态的，也可以算有时间性的 —— 有些店开了几代人，有些来了又走。
  • 线：从酒店到景点的道路和小径用一串线段表示。道路信息通常是静态或有时间性的，但实时路况是动态的地理数据。

同样的地理对象还能关联其他数据，供不同的人用于不同目的：迈阿密每个街区都关联着社会人口统计数据（年龄、性别、族裔、教育、收入）； 迈阿密地处佛罗里达南部，属热带季风气候，有飓风季，还有气温、海平面、风力等随时间变化的自然数据，粒度可以细到街区甚至单栋建筑。

这些信息常常一层叠一层地组合起来。有一类专门的软件叫地理信息系统（GIS），能加载、分析、编辑和可视化地理数据。 比如有机食品连锁超市 Whole Foods 打算在迈阿密开新店，就可以用 GIS 叠加这些图层来选址：

  1. 基础图层：迈阿密的边界、行政区、道路和建筑，其他图层都叠在它上面。
  2. 现有 Whole Foods 门店和竞争对手的位置，帮助判断想扩张、或愿意竞争的区域。
  3. 社会人口统计数据，找出核心客群所在的区域，以及人口正在变化、可能影响经营的街区。
  4. 附近道路的实时负载和拥堵情况，评估顾客到店的便利程度，以及从最近仓库送货的效率。
  5. 在候选区域上叠加历史洪水和浪涌数据，预估和规划飓风风险。

Postgres 内置的几何能力

建筑、湖泊、城市边界、兴趣点都可以用几何形状表示。Postgres 内置了 7 种处理二维空间数据的几何类型：

比如城市边界可以存成 polygon，道路存成 lseg，兴趣点存成 point。Postgres 还有专门的运算符和函数，比如 <-> 算两个对象的距离，<@ 判断前者是否被后者包含： 

-- 酒店在 (10,15)，咖啡店在 (20,17)，相距多远？
SELECT point(10,15) <-> point(20,17);

-- 咖啡店在这栋楼里吗？
SELECT point(10,15) <@ polygon '((0,0),(0,30),(50,30),(50,0))';

但对真实的地理应用来说这还不够：它们需要使用标准的空间参考系中的坐标、计算时考虑地球曲率、能和 GIS 无缝集成……这些超出了内置几何类型的能力，而 PostGIS 扩展可以轻松实现。

PostGIS 的扩展能力

PostGIS 把 Postgres 变成地理空间数据库。它实现了开放地理空间联盟（OGC）的标准，支持基础的 geometry 和 geography 类型， 增加了大量地理数据查询分析函数，借助 Postgres 的索引能力加速搜索，还能和第三方可视化、处理工具集成。

geometry 类型在欧几里得平面上表示地理对象，计算距离、面积、相交等。它需要指定几何子类型（Point、LineString、Polygon…），还可以指定坐标系。 比如用 Web Mercator 投影存兴趣点： 

CREATE TABLE coordinates_plane (
    location geometry(Point, 3857)
);

-- 迈阿密市中心，Web Mercator 坐标（单位：米）
INSERT INTO coordinates_plane (location)
VALUES (
   ST_MakePoint(-8930649.94197805, 2972156.8479390536)
);
★ SRID：空间参考系标识符

SRID（spatial reference system identifier）告诉数据库“这些数字是在哪个坐标系里”。 3857 是 Web Mercator 投影，Google 地图、OpenStreetMap 等很多应用用它在平面上渲染地图，单位是米。 4326 是 WGS 84（1984 世界大地坐标系），用经度、纬度表示位置，和 GPS 一样。 同一个地点，在不同 SRID 下的数字完全不同，混用会出错。

geography 类型用球面模型计算，考虑了地球曲率。默认坐标系就是 WGS 84（SRID 4326，可以省略），坐标是经度在前、纬度在后： 

CREATE TABLE coordinates_sphere (
    location geography(Point, 4326)
);

-- 迈阿密市中心：经度 -80.2253934，纬度 25.782414
INSERT INTO coordinates_sphere (location)
VALUES (
   ST_MakePoint(-80.2253934, 25.782414)
);
⚠ 经纬度的顺序

日常说“北纬 25.78°、西经 80.23°”是纬度在前，但 PostGIS 的 ST_MakePoint(x, y) 是 x = 经度、y = 纬度。写反了，迈阿密就跑到南极洲附近的海里去了。

写书时还没有同时支持 amd64（x86_64）和 arm64 的官方 PostGIS 多架构镜像，只有 amd64 版。按你的系统和 CPU 选一条命令：

docker volume create postgres-postgis-volume

导入 OpenStreetMap 数据集

假设你一周后要和家人去佛罗里达度一个期待已久的假：从墨西哥湾畔的宝藏城市坦帕出发，一路开车横穿全州，到大西洋沿岸的繁华都市迈阿密。 你想提前规划好每一站 —— 用开发者的方式：分析佛罗里达的 OpenStreetMap 数据。

ⓘ 什么是 OpenStreetMap

OpenStreetMap（OSM）是一个由全球志愿者维护的开源项目，绘制并持续更新一张免费的世界地图，你可以在 openstreetmap.org 浏览甚至编辑它。 除了交互式地图，还可以下载底层数据：全世界、某个国家地区，甚至单个建筑或道路。Geofabrik 网站能方便地按大洲、国家、地区下载数据。

用开源工具 osm2pgsql 把佛罗里达的 OSM 数据导入带 PostGIS 的 Postgres。它可以作为 Docker 容器运行，从给定的 URL 下载并导入。先建一个 schema：

CREATE SCHEMA florida;

docker volume create osm2pgsql-volume

docker run --name osm2pgsql --network="host" \
 -e PGPASSWORD=password \
 -v osm2pgsql-volume:/data \
 iboates/osm2pgsql:2.1.1 \
 -H 127.0.0.1 -P 5432 -d postgres -U postgres --schema florida \
 http://d3e4uq6jj8ld3m.cloudfront.net/florida-250501.osm.pbf

docker volume create osm2pgsql-volume

docker run --name osm2pgsql --network="host" `
 -e PGPASSWORD=password `
 -v osm2pgsql-volume:/data `
 iboates/osm2pgsql:2.1.1 `
 -H 127.0.0.1 -P 5432 -d postgres -U postgres --schema florida `
 http://d3e4uq6jj8ld3m.cloudfront.net/florida-250501.osm.pbf

容器会下载 2025 年 5 月 1 日版本的佛罗里达数据并导入，视机器性能大约需要 10 分钟。 （数据最初来自 Geofabrik；想用最新版，或书里的 URL 失效了，可以去 这个页面下载。） --network="host" 让容器使用宿主机网络，从而能通过 127.0.0.1:5432 连到 Postgres 容器。

osm2pgsql_properties 存的是导入时用的参数，另外四张表存真正的地理数据。这些表都有几十列，比如 \d florida.planet_osm_point 能看到 osm_id、access、addr:housename、admin_level…… 但不是每条记录都用到所有列，只有和该 OSM 对象相关的列才有值（各列的含义见 OSM Wiki）。 所有表都有一个 way 列存储坐标，但数据类型不同。

线表

planet_osm_line 存不构成闭合环的 OSM 路径（way）：公路、道路、小径、河流、铁路。planet_osm_roads 是它的子集，为低缩放级别的渲染做了优化。 两张表的 way 列都是 geometry(LineString, 3857)。LineString 用两个或更多有序的点定义一条从起点到终点的路径。找出最短的几条有名字的路径：

多边形表

planet_osm_polygon 存可以表示为闭合路径或多边形的数据：城市、公园、湖泊、建筑。它的 way 列类型是 geometry(Geometry, 3857) —— Geometry 是一个通用子类型，可以存 Point、LineString、Polygon、MultiPolygon 等更具体的类型。这张表里通常是 Polygon（二维闭合平面区域）和 MultiPolygon（一组互不重叠、互不相邻的多边形，比如由好几个岛组成的区域）。

查询地理数据

PostGIS 提供了几十个查询和处理地理数据的函数和运算符。我们回到旅行计划，依次探索三个区域：

处理点：坦帕

这一部分用到的函数：

函数作用

转换和读取坐标

旅行从坦帕开始。先找到代表市中心的那个点（通常对应城市的行政中心，而不是城市边界多边形的几何中心）：

SELECT name, ST_AsText(way) AS coordinates
FROM florida.planet_osm_point
WHERE name = 'Tampa' and place = 'city';

 name  |                 coordinates
-------+---------------------------------------------
 Tampa | POINT(-9179231.997685665 3242389.052874039)
(1 row)

这是 Web Mercator 坐标。想换成 GPS 用的经纬度？转换到 SRID 4326：

SELECT name, ST_AsText(ST_Transform(way, 4326)) AS coordinates
FROM florida.planet_osm_point
WHERE name = 'Tampa' and place = 'city';

 name  |             coordinates
-------+--------------------------------------
 Tampa | POINT(-82.458444 27.947759499952074)
(1 row)

经度在前，纬度在后。可以用它生成一个 OSM 链接，在浏览器里打开就能看到标记：

WITH tampa_city_point AS (
  SELECT ST_Transform(way, 4326) AS coordinate
  FROM florida.planet_osm_point
  WHERE name = 'Tampa' AND place = 'city'
)
SELECT 'https://www.openstreetmap.org/?mlat=' ||
  ST_Y(coordinate) || '&mlon=' || ST_X(coordinate) AS osm_url
FROM tampa_city_point;

                                osm_url
-----------------------------------------------------------------------
 https://www.openstreetmap.org/?mlat=27.947759499952074&mlon=-82.458444
(1 row)

CTE 找到点并转换成经纬度，主查询用 ST_Y 取纬度（mlat）、ST_X 取经度（mlon）拼出链接。打开后地图上的标记就是坦帕市中心。

点与点之间的距离

你订了水街区（Water Street District）中心的 Roost Apartment Hotel —— 坦帕市中心一个充满活力的滨水街区，有公共空间、一流餐厅，步行就能到文化场馆和公园。现在想找步行可达的餐厅： 

WITH roost_hotel AS (
  SELECT way FROM florida.planet_osm_point
  WHERE name = 'Roost Apartment Hotel' AND tourism='hotel'
)
SELECT p.name, p.amenity,
  round(ST_Distance(h.way,p.way)) as distance_meters,
  round(ST_Distance(h.way,p.way) * 3.28) as distance_feet
FROM roost_hotel as h
JOIN florida.planet_osm_point AS p
  ON ST_DWithin(h.way, p.way, 500)
WHERE p.amenity = 'restaurant'
ORDER BY distance_meters LIMIT 5;
  1. CTE roost_hotel 找到酒店的坐标。
  2. 用 ST_DWithin(h.way, p.way, 500) 作为 JOIN 条件，找出离酒店 500 米以内的点，WHERE 再筛出餐厅。
  3. 对每家餐厅用 ST_Distance 算距离，换算成米和英尺，round 取整。
  4. 按距离排序，取最近的 5 家。
          name           |  amenity   | distance_meters | distance_feet
-------------------------+------------+-----------------+---------------
 Wagamama                | restaurant |              68 |           224
 Boulon Brasserie        | restaurant |             132 |           435
 The Pearl               | restaurant |             173 |           567
 3 Corners               | restaurant |             252 |           825
 Fabrica Woodfired Pizza | restaurant |             293 |           962

3857 投影下，ST_DWithin 和 ST_Distance 的单位都是米。

用坐标直接创建点

如果已经知道酒店的坐标（SELECT ST_AsText(way) … WHERE name = 'Roost Apartment Hotel' 得到 POINT(-9178356.224987695 3242002.0503882724)），就不用每次去表里查了：

WITH roost_hotel AS (
  SELECT ST_SetSRID(
    ST_MakePoint(-9178356.224987695, 3242002.0503882724), 3857) as point
)
SELECT p.name, p.amenity,
  round(ST_Distance(h.point,p.way)) as distance_meters,
  round(ST_Distance(h.point,p.way) * 3.28) as distance_feet
FROM roost_hotel as h
JOIN florida.planet_osm_point AS p
  ON ST_DWithin(h.point, p.way, 500)
WHERE p.amenity = 'restaurant'
ORDER BY distance_meters LIMIT 5;

ST_MakePoint 用坐标创建点，ST_SetSRID 声明它属于 3857 坐标系，结果和清单 10.14 一样。

💡 用 EWKT 创建几何对象

也可以一步到位：ST_GeomFromEWKT('SRID=3857;POINT(-9178356.224987695 3242002.0503882724)')。EWKT 是 PostGIS 在 WKT 前面加上 SRID 的扩展格式。

为地理数据建索引

地理数据有点、多边形、线段等各种形状，坐标在二维甚至多维的空间参考系里。普通的 B-tree 应付不了，需要专门的空间索引。 空间索引不存储实际的坐标或形状，而是索引几何对象所在的外接矩形（bounding box） —— 二维空间里一个刚好框住该对象的矩形。 靠它就能快速找出位于某区域内、或和某区域相交的几何对象，跳过无关的。PostGIS 支持三种：

  • GiST（通用搜索树）：把空间划分成能覆盖所有几何对象的外接矩形，大矩形递归拆成小矩形，直到最小的矩形里存着对实际几何对象的引用。地理数据的默认选择，支持的空间运算符和函数最多，各种规模和复杂度的数据都表现良好。
  • SP-GiST（空间划分的通用搜索树）：围绕一个选定的点（质心）把空间分成四个不重叠的象限，每个象限再围绕自己的质心继续细分。适合重叠很少、分布均匀的数据，比如天然不重叠的点。但支持的运算符和函数比 GiST 少。
  • BRIN（块范围索引）：为每个表页范围存一个能框住其中所有几何对象的外接矩形。最大的优点是小，但前提是数据在表里按某种顺序存放（原理和第 9 章的时序数据一样）。

SP-GiST 和 BRIN 用于地理数据的方法见 PostGIS 文档。下面细看通用的 GiST。

GiST 的结构

GiST 是 Postgres 的一种基础索引框架：它实现了底层的索引能力，并暴露一组接口函数，只要为某个数据类型实现这些接口，就能支持新的类型或访问方法。 第 6 章用它索引 tsvector 词素；它还被用来索引网络地址 inet、范围类型 int4range/daterange、pg_trgm 的三元组等等。

PostGIS 用 GiST 为 geometry 和 geography 提供索引，实现了包含、相交等空间函数和运算符的访问方法。具体来说，它在 GiST 之上实现了一棵 R-tree： R 代表 rectangular（矩形），即把空间分成能框住点、线段等数据的外接矩形。查询只需要看那些和目标矩形包含、相交或不相交的部分。

  • 根节点条目存顶层矩形 R1–R5 的边界，它们一起覆盖整个佛罗里达，彼此可以相交。
  • 第二层存更小的矩形，每个都位于某个上层矩形之内。比如 R6–R9 都在 R1 里，所以被 R1 引用。
  • 第二层的矩形是叶子条目，不再引用更小的矩形，而是指向被索引的表数据（这里是点）。比如 R6 引用了 p1、p20 两行。

  1. 数据库做了一个嵌套循环连接（Nested Loop）：外层的每一行都和内层的行比较。
  2. 先算外层，也就是 brickell CTE：用 B-tree 部分索引找到 3 条名叫 Brickell City Centre 的记录，其中 2 条不是车站被过滤掉，剩下 1 行。
  3. 内层用这一行的车站坐标做 Bitmap Index Scan，遍历 GiST 索引：用外接矩形运算符 && 检查每个点是否和 st_expand(车站, 500) 生成的“车站周围 500 米的矩形”相交。得到 1205 个候选。
  4. Bitmap Heap Scan 访问 21 个页，用更精确的 st_dwithin（比较真实距离，而不只是矩形）和 shop IS NOT NULL 过滤，剔除 1169 行，剩 36 行。

GiST 索引完全没用上，Postgres 只好启动多个工作进程并行全表扫描，把佛罗里达所有的商店都拿来算一遍距离。 结论：“在某距离之内”这种条件，永远写 ST_DWithin，不要写 ST_Distance(…) <= N。ST_Distance 留给 SELECT 里计算要显示的距离。

小结

  • PostGIS 把 Postgres 变成地理空间数据库，引入专门的数据类型和大量查询处理函数。
  • geometry 在欧氏平面上用笛卡尔数学计算，简单快速；geography 用球面模型考虑地球曲率，更准但更慢。
  • SRID 标明坐标系：3857（Web Mercator，米）、4326（WGS 84，经纬度）；ST_Transform 在两者之间转换。
  • 几十个空间函数可以查询、创建、转换和处理地理数据：ST_DWithin、ST_Distance、ST_Within、ST_Equals、ST_Intersects、ST_Area、ST_Length……
  • PostGIS 能和 QGIS 等图形化工具集成。
  • 地理查询可以用 GiST、SP-GiST、BRIN 索引优化，GiST 是默认选择；ST_DWithin、ST_Contains、ST_Intersects 等索引感知函数能用上 GiST。
