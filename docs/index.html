为什么是 Postgres？

PostgreSQL（简称 Postgres）诞生于加州大学伯克利分校的研究项目，开源、由社区治理，已经打磨了 35 年。 它首先是一个可靠的关系型数据库：用 SQL 读写，擅长处理大量并发的小事务，就算服务器在操作中途崩溃，数据也不会乱。

但 Postgres 从设计之初就是可扩展的。借助内置能力和几百个扩展，同一个数据库还能存 JSON 文档、做全文搜索、存向量嵌入做语义搜索、分析时序数据、处理地理坐标、充当消息队列…… 于是社区里流行起一句话：“Just use Postgres！” —— 在往技术栈里塞第二个数据库之前，先看看 Postgres 能不能搞定。

这套教程写给谁

  • 会一点 SQL 的应用开发者：知道怎么建表、插数据、查数据就够了。每一章都从“为什么需要它”讲起，配有图解。
  • 用过 Postgres，但只把它当关系库的人：第 5 章起的每一章都可以单独阅读，挑你感兴趣的场景。
  • 正在为新需求选型的工程师和架构师：每章都展示了 Postgres 在该场景下能做到什么、怎么做，以及要注意什么，帮你判断“是不是真的需要另一个数据库”。
ⓘ 需要准备什么

一台装了 Docker 的电脑，和一个终端。所有例子都在 Docker 容器里运行，不会在你的电脑上留下痕迹，也不需要另外安装任何数据库客户端（容器里自带 psql）。 第 8 章的 RAG 原型需要 Python 和 Ollama，但不运行它也能读懂整章。

每一章用什么环境

前 7 章共用同一个官方 Postgres 容器；从第 8 章开始，每章换一个预装了相应扩展的镜像。它们都映射到 5432 端口，所以同一时间只运行一个（每章开头都会提醒你先停掉上一个）。

拿到代码仓库：

git clone https://github.com/dmagda/just-use-postgres-book
cd just-use-postgres-book

以后每章加载数据的方式都一样：docker cp 把数据目录复制进容器，再用 psql 的 \i 执行里面的 SQL 脚本。

💡 懒人方式：docker compose

本站所在的仓库根目录有一个 docker-compose.yml， 把上图所有容器按章节分组成 profile，容器名、卷名都和教程一致。克隆这个仓库后： 

docker compose --profile core up -d        # 第 1～7 章、附录、补充专题 2～6
docker compose --profile pgvector up -d    # 第 8 章（含 Ollama）
docker compose --profile timescale up -d   # 第 9 章
docker compose --profile postgis up -d     # 第 10 章
docker compose --profile pgmq up -d        # 第 11 章
docker compose --profile zh up -d --build  # 专题 1：中文全文搜索

docker compose --profile core down         # 换章节前先停掉上一组（数据卷会保留）

# 仓库的 data/ 目录已挂载到容器的 /data，可以省掉 docker cp：
docker exec -it postgres psql -U postgres -c "\i /data/streaming/streaming_ddl.sql"

怎么用这套教程

  • Postgres 新手：先按顺序读第 1–4 章，它们是所有关系型数据库共通的基础。之后可以跳到任何感兴趣的章节。
  • 有经验的用户：随意挑章节。如果打算读第 2–7 章，先扫一眼第 1 章开头启动 Docker 容器的部分 —— 那几章都复用这个容器。
  • 亲手敲代码：每个代码块右上角都有“复制”按钮；浅色底、标着“输出”的块是预期结果（用了随机数的地方，你的结果会不同）。
  • 看图：每章都有大量示意图，帮你在脑子里建立模型 —— 索引长什么样、事务怎么并发、向量为什么能表示“含义”……
  • 做练习：每章末尾的“动手练习”是在原书示例基础上的延伸，做完会理解得更深。

💡 一句话总结

如果你只记住一件事：“Just use Postgres”不是说 Postgres 能替代一切，而是说 —— 在往技术栈里加第二个数据库之前，先认真看看 Postgres 能不能胜任。 这套教程剩下的 13 页，就是带你亲眼看看它到底能做多少事。之后的 6 个补充专题（中文全文搜索、常用 SQL、RLS、VACUUM、应用接入、备份升级）则补上了原书之外、实际项目里常用的内容。
